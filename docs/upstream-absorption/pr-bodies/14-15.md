Closes #14. Closes #15.

Two changes to `.github/workflows/ci.yml`, both from findings you confirmed
yourself on #12.

## 1. The required status check no longer embeds the Julia version (#14)

```diff
-    name: Julia ${{ matrix.julia-version }} / ${{ matrix.os }}
+    name: Julia tests
```

As you put it, a pin bump would deadlock every PR, because the check name
moves with the matrix while the ruleset's required check does not.

**This needs an owner action to land.** Renaming the job renames the check, so
if the branch ruleset currently requires `Julia 1.12.5 / ubuntu-24.04`, that
entry has to be switched to `Julia tests` before this can merge — otherwise
the PR will sit waiting for a check that no longer exists. I have not touched
any ruleset.

## 2. FastQC and MultiQC are now installed (#15)

`ci.yml` installed cutadapt, cd-hit, vsearch and swarm; FastQC and MultiQC
appear zero times while eight files under `src/` call them, so the prefilter
QC stage never ran in CI.

Both are installed from `config/defaults/tool_versions.yml` — the same pin
file the other tools come from, so nothing new is introduced:

* **MultiQC 1.33** — `pip install "multiqc==$VERSION"`, as a PyPI spec exactly
  like cutadapt, with the version read from the pin file into `MULTIQC_SPEC`.
* **FastQC 0.12.1** — downloaded from the pinned URL and refused unless it
  hashes to the pinned SHA256, then the launcher is moved to
  `/usr/local/bin/fastqc`. Same rule vsearch and swarm already follow. The pin
  file records the archive hash, not a binary hash, because the archive is the
  only artefact the installer sees before it has to trust it.

The three new pins are read in the existing "Read pinned versions" step, so
they cannot drift from the pin file.

## What this does not change

No test step, no job matrix, no dependency and no pin. The only steps added
are two installs; the only step edited is the pin reader. The job name change
is a rename of the check, not of the job id (`test`), so `concurrency`,
`needs`-free ordering and the artifact names are unaffected.

## How to run the tests

```sh
julia --project=. -e 'import Pkg; Pkg.instantiate()'
julia --project=. test/runtests.jl            # unit suite
julia --project=. -t4 test/runtests.jl --integration
```

## Honest limitation

I have no Julia, R or bun toolchain in the environment this was authored in,
so I could not execute the suite here. What I did instead was keep every
change off the test path: the diff adds two install steps and edits the pin
reader and the job name. If the installs fail, they fail as their own red
step, not as a mysterious test failure.
