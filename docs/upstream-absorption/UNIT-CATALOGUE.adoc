*Read this with* link:UPSTREAM-SYNC-STATE.md[UPSTREAM-SYNC-STATE.md] (the
six merge conditions) and link:OWNER-FEEDBACK.md[OWNER-FEEDBACK.md] (what he
has already said yes and no to).

Every row is one branch, one PR, one decision. Units are **stacked**: each is
branched from current upstream `main` and re-applies its own file set, so any
unit can be refused without disturbing the others that have already landed.
Where two units genuinely depend on each other the dependency is named.

*Verdict key*

`ON HIS LIST`:: named in his condition 2 — send it, it is expected.
`ASK FIRST`:: not on the list; needs an issue and a yes (his condition 2, last
line).
`REFUSED`:: he has already said no. Listed only so it is not re-sent.
